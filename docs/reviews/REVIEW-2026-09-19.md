# Memory framework review — 19 September 2026

## Scope and result

Reviewed the fixes from `8262cf3` through `e620fff`, the working-tree release-smoke change, and the framework's ingestion, retrieval, awareness, lifecycle and host-integration boundaries. Six remaining runtime correctness gaps and one test defect were independently reproduced with temporary databases and injected failures. Runtime implementation was not changed.

The accompanying [function inventory](function-calls-2026-09-19.md) covers **58 Python modules, 689 named functions and 7,889 call expressions** under `personal_memory`. The [JSON inventory](function-calls-2026-09-19.json) includes imports, qualified function names, definition ranges and individual call sites. It is a syntactic inventory, not a dynamically resolved graph: callbacks, polymorphic backends, subprocess adapters and HTTP route dispatch must be read with the flows below. It does not prove every branch has been exercised. Tests, scripts, third-party dependencies and the separate Hermes repository are outside this inventory.

## Remaining findings

### R1 — P1: An empty archive cannot initialize semantic indexing

Location: `personal_memory/semantic.py`, `SemanticIndex._activate`, line 242.

`semantic_seq` is initialized only when `_next_seq` receives work. On a fresh empty database, `_reconcile` emits no signals and `_activate` dereferences `fetchone()[0]` on an empty sequence table. Reproduction: `Store(temp_path)` followed by `SemanticIndex(store, embedder=FakeEmbedder())` raises `TypeError: 'NoneType' object is not subscriptable`.

The service warms semantic retrieval before ingestion. `Hybrid._ensure_semantic` turns initialization exceptions into a permanent `_semantic_failed` state, so later arriving mail does not recover semantic indexing in that running process. Keyword storage continues, making this degradation easy to overlook.

Core fix: initialize the sequence singleton transactionally as a schema invariant, including fresh and migrated databases. Test empty startup, first ingestion after warm-up, reopen, and migration of an empty legacy queue. The service-level test must assert that semantic initialization remains available after an empty startup.

### R2 — P1: Switching models can permanently lose an unfinished indexing obligation

Location: `personal_memory/semantic.py`, `SemanticIndex._activate`, lines 241–250.

The per-model progress watermark advances when work is **enqueued**, while the shared work row can be consumed by another model. History is then pruned using those activation watermarks. A model that has not completed its queued work can therefore have neither vectors, pending work nor replay history when it returns.

Reproduced sequence: ingest one record; initialize model A without syncing; initialize B and sync B; reopen and sync A. Result: **A has zero vectors and the shared queue is empty**. The same condition can arise after a failed A embedding attempt or shutdown before A drains its backlog.

Core fix: make outstanding obligations durable per model, or persist a per-model completion watermark with sufficient replay/reconciliation information. Queue insertion is not completion. Add A→B→A tests with A never drained, A partially drained, A failed, and history retention exhausted; check actual candidate retrieval, not only queue size.

### R3 — P2: A failed HNSW insertion is treated as successfully published on retry

Location: `personal_memory/semantic.py`, `SemanticIndex._add`, line 275, and `_publish`, lines 361–363.

`_add` inserts the label into `self.rows` before `index.add_items` succeeds. `_publish` uses membership in `self.rows` as proof of publication. If the accelerator insertion raises, the next retry skips it, creates `vector_done`, and removes the work row.

Reproduced with an accelerator whose first `add_items` raises: after two sync passes there was **one insertion attempt, one completion marker, and zero queued obligations**. The running accelerator never received the vector. Durable chunks survive, so a successful rebuild on restart can mask the problem.

Core fix: publish the in-memory bookkeeping only after the accelerator confirms insertion, with a defined rollback/retry strategy for partially successful backend calls. Inject failures inside `add_items`, initialization and resize, not just around the outer `_add` call. Assert candidate availability after retry without restart or re-embedding.

### R4 — P1: ASGI releases ownership and reports completion after service shutdown fails

Location: `personal_memory/asgi.py`, `Application.__call__`, lines 107–116; related startup cleanup at lines 85–86.

The result of `_release('service')` is discarded. If `MemoryService.close()` reports a live worker, shutdown still releases the Hindsight runtime and process lease and emits `lifespan.shutdown.complete`. Reproduced using a resource whose close raises: the service remained retained, the lease closed, and ASGI reported successful shutdown.

`_release_all` also releases prerequisites after a dependent resource fails; startup ignores its result and can replace retained fields. Keeping a reference to an unfinished resource is insufficient if its ownership lease has already been released.

Core fix: make teardown dependency-aware. Keep ownership and required runtime resources until dependents have drained; propagate incomplete close to `lifespan.shutdown.failed`; prevent startup from constructing replacements while cleanup remains incomplete. Test the real ASGI lifespan boundary, repeated shutdown, and startup after failed cleanup.

### R5 — P1: Slow semantic warm-up can resume as a writer after the indexing lease is released

Location: `personal_memory/retrieval.py`, `Hybrid.close`, lines 208–223, and `_ensure_semantic`, lines 187–198.

Close gives warm-up a grace period but releases the indexing lease while that thread can still be constructing `SemanticIndex`. The constructor loads the model before activating/reconciling the database queue. `_ensure_semantic` then publishes the engine and starts a worker without checking shutdown again.

Reproduced by gating the constructor: start warm-up; close with zero grace; acquire the same indexing lease as a second owner; release the old constructor. The old owner resumed construction and published its engine after ownership had moved. In the real constructor, activation includes queue/progress writes.

Core fix: include initializing writers in the ownership lifecycle. Either retain the lease and report incomplete shutdown until initialization drains, or split cancellable read-only model loading from an ownership-checked index activation. Add a gate immediately before database activation and prove that no old-owner write can occur after a second owner acquires the lease.

### R6 — P2: An incomplete source page can acknowledge the new-data signal

Location: `personal_memory/source_runtime.py`, `SourceRuntime.tick`, lines 258–263; `source_sync.py`, `SyncWorker.run_once`, lines 790–795.

The runtime considers a feed caught up whenever `more` is false. It ignores `page_complete`, even though `commit_page` deliberately does not advance the checkpoint for an incomplete page. The public page validator permits `complete=False, more=False` (including the default for `more`).

Reproduced with a `CoverageAdapter` returning an incomplete page: after one tick **pending signals = 0, cursor = None**. The request to catch up was acknowledged despite the unchanged checkpoint; the next pass was delayed by the normal poll interval.

Core fix: require both successful checkpoint completion and no continuation before acknowledging coverage. Define/enforce the relationship between `complete` and `more` at the SDK boundary, preserving old adapter compatibility. Test incomplete empty and nonempty pages, missing `more`, mixed streams, retry/replay and recovery to a complete page.

### R7 — P2: Prefetch reuse tests still discard the first successful packet

Location: `tests/test_memory.py`, lines 481–485, 502–504, 524–526 and 647–659.

These tests call `prefetch`, permit its first result to be either pending or a packet, then unconditionally wait for another packet. A successful first response marks its evidence injected; subsequent identical requests correctly return an empty, suppressed result. The helper polls for 90 seconds and fails without reaching the reuse/filter assertions.

Reproduced `test_explicit_fast_search_reuses_completed_automatic_prefetch` with a three-second first-response wait and the helper timeout shortened to 0.5 seconds: `prefetch never reached state 'packet'; last observed suppressed: ''`. This exposes the same sequence without a 90-second delay. The normal full-suite run is recorded separately below.

Core fix: let the helper consume an already-observed result, or call it only if the first result was pending. Add explicit tests of immediate completion and delayed completion. Do not disable suppression or weaken the reuse assertions to make these tests pass.

## Function-call flows

### 1. Service construction and ownership

```text
CLI/setup/configuration
  → ASGI Application.__call__(lifespan.startup)
  → ProcessLease(service.lock)
  → hindsight_runtime.Runtime.start
  → MemoryService.__init__ → _construct
      → Store.__init__ → schema setup / deletion recovery / lifecycle.apply_upgrade
      → backend.load_backend → Hybrid.__init__ → ProcessLease(indexing.lock)
      → Learning / AdaptiveRecall / Intelligence / Investigation
      → Workflows → reset.initialize → Workflows.start
      → SourceRuntime → registered source adapters / routes
  → Hybrid.start_warmup → warmup → _ensure_semantic → SemanticIndex
```

Service credentials/roles and capability checks live in `authenticate`, `authorize` and `_dispatch`. The HTTP adapter is transport, not the authority for source scope or execution permission. Source and workflow workers can operate without an active Hermes conversation. Shutdown reverses these relationships, subject to R4/R5.

### 2. Hermes conversation capture and durable delivery

```text
PersonalMemoryProvider.initialize
  → configuration / access checks / Client / Outbox / Lineage
Hermes on_turn_start / sync_turn / observe_tool_result / on_host_event
  → provider._capture_event
  → Outbox.enqueue → durable local retry state
  → Outbox.flush → Client.call(/v1/ingest)
  → MemoryService.authenticate / dispatch → authorize / _dispatch → ingest
  → ingestion.validate_batch / extension validation
  → Store.ingest_contract → Store.ingest → _apply_ingest_item
      → immutable record / FTS / participants / receipt / audit
      → semantic.enqueue(index)
      → changes.append
```

Stable source IDs and revisions provide replay identity. Duplicate content at the same revision does not require another embedding; changed content must use a new revision. The direct-ingest journal identifies imported material as historical; source-sync is the richer path for live arrivals, source heads and catch-up semantics.

### 3. Historical and continuous source ingestion

```text
SourceRuntime.connect_gmail
  → protected credential storage / adapter.check / SourceSync.configure
SourceRuntime._run → tick
  → active connections → take_signals → _declarations
  → scheduling by stream / partition / mode
  → SyncWorker.run_once → SourceSync.claim
  → adapter.discover (unless declarations supplied)
  → adapter.read_page(context, read_state)
  → SourceSync.commit_page
      → validate_page / page_digest / lease + generation + epoch fences
      → _apply_operation → Store._apply_ingest_item / _retire
      → canonical source head / receipts / metadata / jobs / coverage
      → changes journal / semantic work
      → checkpoint (only for complete pages)
  → SourceSync.release
  → runtime schedule / acknowledge captured signals after all required feeds
  → SourceRuntime._attachment → adapter.attachment → blob lifecycle
```

Gmail `read_page` backfill lists messages, then `_message` fetches and `normalize` produces canonical evidence. Incremental mode consumes the Gmail history cursor, freezes an upper boundary for a paging pass and declares `more` while its offset/page continues. Historical and incremental passes are interleaved. Source version ordering keeps a late historical page from replacing a newer live head. Polling and durable signals converge on the same core worker; a webhook should trigger this path, not implement a second ingestion engine.

Extension boundary: `SourceAdapter.spec/check/discover/read_page/normalize`, with optional attachment/event/subscription/state-migration hooks. `SourceSync` owns durable state and canonical commit; adapters own upstream transport and normalization. Declaring an optional hook does not by itself schedule or expose that hook: new sources must verify runtime wiring for their trigger/subscription requirements.

### 4. Semantic and Hindsight processing

SQLite is the canonical evidence and lifecycle store; using it does not make this “only SQL storage.” Semantic vectors provide meaning-based candidate lookup. R1–R3 affect semantic availability, not whether canonical ingestion occurred.

The service records supplied packets separately from proven model exposure. Background analysis uses the host's model lifecycle rather than adding an unrelated agent runtime. ### 8. Curated memory, native Hermes state and provenance

```text

```

The provider is the integration point for Hermes native memory surfaces. Profile/default-home resolution must remain consistent across the provider, awareness worker and scheduler. ### 9. Retirement, forgetting, reset and recovery

```text
Source replacement / Store.supersede → lifecycle.retire
  → descendants → record_visibility
  → awareness / learning / curated invalidation
  → identity revocation / claims become retired history
  → semantic retirement obligation
Store.forget / forget_source → DeletionLedger intent → Store._forget
  → canonical/dependent data scrub + index deletion obligations
reset.reset → durable reset token → epoch increment / worker fencing
  → pause sources / cancel jobs → reset.resume → forget_source
  → Hybrid.clear_external → Hindsight.clear_bank (durable retry on failure)
recovery.backup → consistent database copy + encrypted archive
recovery.restore → isolated integrity checks + deletion-ledger handling
```

Retirement preserves explicitly requested history; forgetting removes content and blocks resurrection. These must not be conflated. Canonical visibility checks protect recall while derived indexes catch up. Restore/reset and external-engine cleanup require separate completion reporting.

## Efficiency opportunities after correctness fixes

These are code-backed optimization candidates, not measured performance claims.

1. **Keep Hindsight idle work bounded.** `_index_pass` still selects through the archive with anti-joins on every poll, and its deletion list is unbounded. Consider durable targeted obligations with a bounded repair path, preserving the lost-ack deletion guarantee. Measure idle SQL cost and deletion-drain latency with a large mailbox before changing it.
2. **Batch semantic embedding across records.** `sync(batch=8)` drains multiple records, but `_embed_record` calls `documents` per record. Batch compatible chunks across records within a byte/token budget, retaining independent commit/retry outcomes and final lifecycle checks. Measure requests, throughput and p95 live-arrival delay during backfill.
3. **Reduce consolidation call overhead.** `Workflows.scan` produces overlapping 2,000-character jobs every 1,800 characters; each adapter run creates a subprocess and may call the LLM. A bounded multi-span batch can amortize this, provided citations, retirement invalidation, retries and idempotency remain per evidence unit. Test long mail threads and quoted repetitions without discarding original evidence.
4. **Avoid redundant host round trips only with explicit freshness.** Prefetch currently checks generation even on cached results, while awareness is fetched separately. A combined bounded service response or versioned change token could reduce requests. Preserve independent awareness refresh, canonical deletion checks and prompt-exposure receipts.
5. **Make non-Gmail catch-up termination part of the SDK.** Incremental completion now uses `more`, but runtime backfill/reconcile scheduling still reads a `cursor['done']` convention. A source-neutral terminal state would make future adapters easier to implement consistently. Provide a compatibility migration and adapter contract tests.
6. **Expose end-to-end stage lag.** Report source checkpoint lag, canonical commit age, embedding backlog, extraction backlog, awareness exposure and delivery separately. “Stored,” “searchable,” “summarized,” “shown to Hermes” and “delivered” are different completion states.
